# AGENTS.md

MTurrets is a Kotlin NeoForge mod (MC 1.21.1) porting Mindustry's turret, machine, and material gameplay into Minecraft. Mod id, resource namespace, and package are all `mturrets` (package `xyz.luobo.mturrets`). Key platform / identity / dependency trade-offs live in `docs/adr/0001-renovation-decisions.md`;

## Build & run

- JDK 21; `gradlew build` builds, `gradlew runClient` smoke-tests the client
- Version coordinates are centralized in `gradle/libs.versions.toml`; runtime deps are only GeckoLib / KotlinForForge / Jade (rationale in ADR-0001 §3)
- `gradlew runData` regenerates `src/generated/resources` — this directory is committed, and CI gates its freshness with `git diff --exit-code`. After touching registries, block/item models, or lang keys, re-run and commit the output or CI fails
- `gradlew runGameTestServer` runs the behavior regression suite (damage / energy / output, external behavior only); run it locally, CI does not
- The Chinese mirror repositories in settings.gradle are pre-existing environment; keep them

## Language & naming

- Player-visible text goes through lang files: `zh_cn.json` is hand-maintained, `en_us.json` is generated by datagen. Adding visible content = edit `zh_cn.json`, then `runData` to refresh `en_us.json`
- Domain vocabulary follows the `CONTEXT.md` glossary (honor each entry's `_Avoid_` synonyms)

## Upstream references

- Porting Mindustry content (turret / bullet / material stats, lead aiming), sourcing original art, or making a non-trivial NeoForge design call → `docs/reference/upstreams.md` (clone commands, pinned commits, asset index, license boundaries)
- Work-in-progress art (Blockbench `.bbmodel`, raw PNGs) lives in root `assets/`, which is gitignored and therefore absent on a fresh clone; only finished exports go into `src/main/resources/assets/mturrets/` and get committed
- Third-party agent skills are not committed: `.agents/` is gitignored, rebuild it after cloning with `npx skills experimental_install` (driven by the committed `skills-lock.json`)
